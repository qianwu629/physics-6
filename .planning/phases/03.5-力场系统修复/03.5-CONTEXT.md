# Phase 3.5 上下文 — 力场系统修复

## 紧急插入原因

Phase 3（通用力场系统）执行完毕后，在集成测试和下游阶段（Phase 4 表达式驱动外加力）准备过程中，发现力场系统存在**根本性设计缺陷**，阻塞后续开发。具体表现为：

1. **API 语义不一致**：`applyForce` vs `addForce` 混用，与 Rapier 实际 API 不匹配
2. **力场计算与渲染耦合**：VectorRenderer 中力场力计算逻辑侵入可视化层，违反分层架构
3. **设计决策在实现中被推翻**：Phase 3 CONTEXT 中锁定的若干决策在代码中未正确落地或被后续修改覆盖

Phase 3.5 的目标是**系统性回顾和修复**这些设计缺陷，而非简单打补丁。修复完成后，Phase 4 才能安全地建立在稳定的力场架构之上。

## 本阶段目标

彻底修复 Phase 3 力场系统的设计缺陷和实现偏差，确保：
1. 力场 API 与 Rapier 语义完全一致
2. 力场计算与可视化渲染正确分层
3. Phase 3 锁定的设计决策在代码中得到忠实执行
4. Phase 4（表达式驱动外加力）可安全建立在修复后的力场架构上

## 范围边界

**在范围内：**
- Rapier 力注入 API 统一（applyForce/addForce 修正）
- 力场计算逻辑从 VectorRenderer 中抽离，回归力场层
- ForceFieldSystem 与 ForceFieldRenderer 的接口契约重新审视
- 力场力的可视化正确集成到现有矢量系统
- Phase 3 设计决策与代码实现的一致性审计
- 相关单元测试修复和补充

**不在范围内：**
- 新增力场类型或力场功能
- Phase 4 表达式解析器的实现
- UI 界面改动（除非必要修复）
- 性能优化（Phase 6 处理）

## 成功标准

1. [x] `ForceFieldSystem` 中力注入 API 与 Rapier 官方 API 完全一致（已修复磁场力绕过 addForce 的能量守恒方案）
2. [x] `VectorRenderer` 中不再包含力场计算逻辑，仅负责渲染（已在 Phase 3 Review Fix 中完成）
3. [x] Phase 3 CONTEXT 中所有锁定决策在代码中有明确对应
4. [ ] 所有力场相关测试通过（含新增回归测试）—— 待补充磁场能量守恒回归测试
5. [x] Phase 4 可安全接入力场系统（表达式力与力场力正确叠加）
