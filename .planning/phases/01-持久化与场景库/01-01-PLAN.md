**sceneValidation.ts** — 定义序列化数据结构和 Zod Schema：

```typescript
// 序列化场景数据结构（D-01-01 最小集 — 不含 UI/摄像机/可视化状态）
// schemaVersion: "1.0" 固定
// savedAt: ISO 8601 时间戳字符串
// simulation.environment: 全局物理环境参数
// simulation.entities: 实体数组（含所有组件）
// simulation.constraints: 约束实体数组（componentType='constraint' 的实体从中过滤）
```

具体实现：

1. 定义 `SerializedComponent` 类型：每种组件类型对应一个接口，使用 discriminant union (type 字段区分)。所有组件字段与 ECS types.ts 中的组件接口一致，但使用普通对象而非 Map。约束实体（constraint）的 `entityAId` 和 `entityBId` 保持为字符串引用。

2. 定义 `SerializedEntity` 接口：`{ id: string; name: string; components: Record<string, SerializedComponent> }` — components 使用对象（键为 ComponentType 字符串）而非 Map。注意约束实体只包含 constraint 类型组件（无 transform/rigidBody 等）。

3. 定义 `SceneData` 接口：`{ schemaVersion: "1.0"; savedAt?: string; simulation: { environment: EnvironmentState; entities: SerializedEntity[]; constraints: SerializedEntity[] } }`

4. Zod Schema 实现（按 D-01-02 宽容模式）：
   - `EnvironmentSchema`: gravity 为 `z.tuple([z.number(), z.number(), z.number()]).default([0, -9.81, 0])`，frictionScale/restitutionScale 默认 1.0，drag 默认 0.1
   - `TransformSchema`: position/rotation/scale 均为 `z.tuple([z.number(), z.number(), z.number()])`
   - `RigidBodySchema`: kind 为 `z.enum(['dynamic', 'fixed'])`，mass ≥ 0，restitution/friction ∈ [0,1]
   - `ColliderSchema`: shape 为 `z.enum(['sphere', 'cuboid', 'cylinder'])`，params 使用 discriminated union 按形状区分字段
   - `VelocitySchema`: linearVelocity/angularVelocity 为 `z.tuple([z.number(), z.number(), z.number()]).default([0,0,0])`
   - `MaterialSchema`: color 为 hex string，roughness/metalness ∈ [0,1]
   - `ComponentSchema`: `z.discriminatedUnion('type', [TransformSchema, RigidBodySchema, ColliderSchema, VelocitySchema, MaterialSchema, ConstraintSchema])`
   - `EntitySchema`: `z.object({ id: z.string().min(1), name: z.string(), components: z.record(ComponentSchema) })`
   - `ConstraintEntitySchema`: 仅含 constraint 组件的实体
   - `SceneSchema`: schemaVersion 固定为 "1.0"，simulation 包含 environment + entities + constraints

5. `validateSceneJSON(json: unknown): ValidationResult` 函数：
   - 先检查 `(json as any)?.schemaVersion`，不匹配时记录 warning（D-01-02）
   - 调用 `SceneSchema.safeParse(json)`
   - 过滤 unknown_keys 类型的 Zod issue，记录为 warning 而非 error
   - 使用 `Object.keys(json)` 检测未知顶层字段，记录 warning
   - 返回 `{ success: boolean; data?: SceneData; warnings: string[]; errors: string[] }`

6. `isVersionMismatch(json: unknown): boolean` — 辅助函数，检查 schemaVersion !== "1.0"

**sceneSerializer.ts** — 核心序列化/反序列化逻辑：

1. `exportSceneToJSON(state): string` 函数：
   - 从 store state 提取 `entities: Map<string, Entity>` 和 `environment: EnvironmentState`
   - 调用 `serializeScene(state)` 得到 SceneData 对象
   - `JSON.stringify(sceneData, null, 2)` 返回格式化 JSON 字符串

2. `importJSONToScene(json: string): ValidationResult` 函数：
   - 检查字符串长度，超过 5MB 时拒绝（D-01-08：`json.length > 5 * 1024 * 1024`）
   - `JSON.parse(json)` 包裹在 try/catch 中，语法错误时返回 `{ success: false, errors: ['JSON 语法错误: ...'] }`
   - 解析成功后调用 `deserializeScene(parsedJson)`

3. `serializeScene(state: { entities: Map<string, Entity>; environment: EnvironmentState }): SceneData` 函数（核心序列化）：
   - 按 D-01-01 最小集：environment + entities（不含 trail/vector）+ constraints
   - 遍历 `state.entities`，对每个 Entity：
     - 遍历 `entity.components`（Map<ComponentType, Component>），**排除** `trail` 和 `vector` 组件（D-01-01 不保存可视化状态）
     - 将剩余组件转为普通对象 `{ [type]: component }`（不是 Map，JSON 兼容）
     - 对于 constraint 组件，保留 `entityAId`、`entityBId`、`kind`、`params`
   - 将非 constraint 实体放入 `simulation.entities` 数组，constraint 实体放入 `simulation.constraints` 数组
   - 设置 `schemaVersion: "1.0"`，`savedAt: new Date().toISOString()`
   - 重要：不保存 Entity 的 `trail` 和 `vector` 组件到 JSON，也不保存任何 UI 状态

4. `deserializeScene(json: unknown): { success: boolean; data?: { entities: Map<string, Entity>; environment: EnvironmentState }; warnings: string[]; errors: string[] }` 函数（核心反序列化）：
   - 调用 `validateSceneJSON(json)` 进行 Schema 校验
   - 如果不 success，直接返回 errors
   - 如果 success，从 `validated.data` 构建运行时状态：
     a. `environment` 直接从 `data.simulation.environment` 取（用 `{ ...DEFAULT_ENVIRONMENT, ...data.simulation.environment }` 合并默认值）
     b. 遍历 `data.simulation.entities`，对每个 `SerializedEntity`：
        - 调用 `createEntity(entity.id, entity.name, [])` 创建空 Entity（工厂函数会自动附加 trail 和 vector 组件）
        - 遍历 `entity.components` 对象（非 Map），将每个组件通过 `newComponents.set(type, component)` 重建到 entity.components Map 中
        - 重要：createEntity 已经附加了 trail 和 vector 默认组件，反序列化时不覆盖它们（保持工厂默认值——trail visible=true, vector showVelocity=true, showForces=true）
     c. 遍历 `data.simulation.constraints`，同样调用 createEntity 并重建约束组件
     d. 检查 constraint entity 引用的 entityAId/entityBId 是否在已创建的 entities 中存在（D-01-08 引用失效跳过逻辑：失效的约束记录 warning 并跳过，不阻断加载）
   - 合并 `validateSceneJSON` 返回的 warnings 和自己的 warnings，一并返回

5. 类型导出：从 sceneValidation.ts re-export `SceneData`, `SerializedEntity`, `SerializedComponent`, `ValidationResult`

| T-01-01 | Tampering | deserializeScene() | mitigate | Zod safeParse 校验所有字段类型；仅提取已知字段，丢弃未知字段；不使用 JSON.parse reviver |
