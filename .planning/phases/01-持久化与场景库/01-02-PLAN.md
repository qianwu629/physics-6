**1. `frontend/src/store/snapshotSlice.ts`** — 新建：

```typescript
import type { StateCreator } from 'zustand';
import { persist } from 'zustand/middleware';
import type { EnvironmentState } from './simulationSlice';
// 注意：快照中存储的是序列化后的场景数据（不是活 Entity Map）
// 这样可以避免 Map 序列化问题（Pitfall #1）
```

定义类型：
- `SnapshotData` 接口：存储场景的完整可序列化状态
  - `environment: EnvironmentState` — 全局环境参数
  - `entities: Array<{ id: string; name: string; components: Record<string, any> }>` — 实体数组（Map 已转为 Array）
  - `constraints: Array<{ id: string; name: string; components: Record<string, any> }>` — 约束实体数组
- `Snapshot` 接口：
  - `name: string` — 用户命名
  - `createdAt: string` — ISO 8601 时间戳
  - `entityCount: number` — 快照时的实体总数
  - `data: SnapshotData` — 序列化场景数据

`SnapshotSlice` 接口：
- `slots: (Snapshot | null)[]` — 5 个槽位（索引 0-4）
- Actions:
  - `saveSnapshot(slotIndex: number, name: string, store: { entities: Map<string, Entity>; environment: EnvironmentState }) => { success: boolean; error?: string }`
    - 将 store.entities Map 转为 Array：`Array.from(store.entities.entries()).map(([id, entity]) => ({ id, name: entity.name, components: Object.fromEntries(entity.components) }))`
    - 分离 constraint 实体到 constraints 数组
    - 设置 createdAt 为 `new Date().toISOString()`
    - entityCount = store.entities.size
    - **保存前不自动检查重名**（重名校验由 UI 层 SnapshotManager 在调用 saveSnapshot 之前完成，以支持覆盖确认流程）
  - `loadSnapshot(slotIndex: number) => Snapshot | null` — 返回槽位数据（由 SceneLoader 统一执行恢复流程 D-01-03）
  - `renameSnapshot(slotIndex: number, newName: string) => { success: boolean; error?: string }` — 空槽位 no-op，检查重名
  - `deleteSnapshot(slotIndex: number) => void`
  - `isNameDuplicate(name: string, excludeIndex?: number) => boolean` — 检查名称是否已被占用

使用 Zustand `persist` 中间件：
```typescript
export const useSnapshotStore = create<SnapshotSlice>()(
  persist(
    (set, get) => ({
      slots: Array(5).fill(null),
      // ... actions
    }),
    {
      name: 'physis-snapshots', // localStorage key
      partialize: (state) => ({ slots: state.slots }), // 只持久化数据，不持久化函数
      version: 1,
    }
  )
);
```

关键注意事项（Pitfall #1）：
- 快照 data 中 entities 和 constraints 使用普通对象/数组存储（不是 Map），避免 JSON.stringify 丢失 Map 内容
- persist 的 partialize 只导出 slots 数组
- saveSnapshot 内部完成 Map→Object 转换

persist 配置:
- `name: 'physis-snapshots'` — localStorage 键名
- `partialize: (state) => ({ slots: state.slots })` — 只持久化数据
- 使用 `createJSONStorage(() => localStorage)` 显式指定（Zustand v5 默认 localStorage，但显式声明更清晰）
- localStorage 写入捕获 QuotaExceededError（Pitfall #4）—— 在 saveSnapshot 中用 try/catch 包裹 set()

**内部布局（从上到下）：**

1. **保存区域** — 顶部输入区：
   - `<Input>` 文本框（placeholder="输入快照名称"）+ `<Button>` 保存按钮
   - 保存按钮点击逻辑：
     a. 校验名称（D-01-06 正则 `^[\w\s\-\.一-龥]{1,30}$`）
     b. 空名称 → 显示红色错误文字 "名称不能为空"
     c. 名称不合法 → 显示 "名称仅支持中英文、数字、空格和 - _ . （1-30字）"
     d. 调用 `useSnapshotStore.getState().isNameDuplicate(name)` 检查重名
     e. 重名 → 显示 "名称已被使用"
     f. 选择目标槽位（空槽位优先，已有槽位需确认覆盖）
     g. 获取当前 store 状态：`const store = useSimulationStore.getState()`，传入 entities 和 environment
     h. `saveSnapshot` 包裹 try/catch，捕获 `QuotaExceededError` 时 `toast.error('存储空间不足，请删除旧快照后重试')`（D-01-08）
     i. 保存成功后清空输入框

2. **槽位列表** — 主体滚动区域：
   - 5 个槽位卡片（索引 0-4），使用 `<ScrollArea>` 包裹（如果已有 scroll-area）
   - 空槽位显示：灰色占位卡片，文字 "槽位 {index+1} — 空"，无操作按钮
   - 已使用槽位显示：卡片内行内布局
     - 左侧：快照信息（名称 + 创建时间 + 实体数标签）
     - 右侧：操作按钮组 [加载] [重命名] [删除]（使用小型 variant="ghost" 按钮 + lucide 图标）
     - 名称支持双击切换到 inline 编辑模式（input 替代文本 span）

3. **槽位操作按钮逻辑：**
   - **加载** → 调用 `loadSnapshot(index)` 获取快照数据 → 交给 `loadSceneWithConfirm`（由 SceneLoader 提供，Plan 03 实现）。此处暂时先通过 props callback 或 store action 触发。由于 Plan 03 (SceneLoader) 还未创建，这里预留接口：`onLoadSnapshot?: (snapshot: Snapshot) => void` prop。
   - **重命名** → 双击名称进入 inline 编辑模式：
     - 显示 `<Input>` 替代文字
     - 默认值 = 当前名称
     - 按 Enter 或 blur 时提交
     - 校验同上（1-30 字符正则 + 重名检测）
     - 有效则调用 `renameSnapshot(index, newName)`
     - 无效则保持编辑状态，显示错误文字
   - **删除** → 弹出确认 Dialog：「确定要删除快照 "{name}" 吗？此操作不可撤销。」确认后调用 `deleteSnapshot(index)`

4. **覆盖确认** — 当用户在保存区输入名称后选择已有数据的槽位时：
   - 弹出 `<Dialog>`：`槽位 '{slotIndex + 1}' 已有快照 '{existingName}'，覆盖后将丢失原数据。继续？`
   - 确认 → 执行 saveSnapshot，取消 → 不操作

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | snapshotSlice rehydrate | mitigate | Zustand persist 的 `migrate` hook 可处理版本迁移；加载时 Zod 校验快照数据结构 |
