## 目标引擎选择

| Option | Description | Selected |
|--------|-------------|----------|
| 轻量纯JS方案 | Cannon.js、Matter.js(2D)、Planck.js 等。体积小、无WASM加载开销，但功能覆盖有限，电磁学仍需自定义。 | |
| 功能丰富的WASM方案 | Ammo.js(Bullet)、PhysX.js、Jolt Physics 等。功能全面（可能含软体/流体），但WASM体积大、加载慢、与R3F集成复杂。 | |

**User's choice:** 两者都评估
**Notes:** 用户要求全面比较轻量纯JS和功能丰富WASM两类引擎，不预设偏好。

## 触发迁移的痛点

| Option | Description | Selected |
|--------|-------------|----------|
| 电磁学功能缺失 | Rapier 仅支持刚体动力学，缺少内置电磁学、软体、流体等物理模型。需要通过自定义力场 workaround 实现。 | ✓ |
| 性能或稳定性瓶颈 | Rapier WASM 在特定场景下（大量实体/复杂约束）出现性能下降或数值不稳定。 | |
| 两者兼有 | 既有功能缺失（电磁学深度支持），也有性能/稳定性方面的顾虑。 | |

**User's choice:** 电磁学功能缺失
**Notes:** 核心痛点明确为电磁学功能缺失，而非性能或稳定性问题。

## 迁移策略

| Option | Description | Selected |
|--------|-------------|----------|
| 大爆炸替换 | 选定引擎后，一次性替换Rapier及相关组件，完成后统一测试。风险高但无中间态。 | ✓ |
| 渐进式迁移 | 先创建引擎抽象层，逐步将实体/系统迁移到新引擎，期间双引擎并行。周期长但风险可控。 | |
| 仅做PoC评估 | Phase 8 只做技术调研和一个代表性场景的PoC验证，实际迁移放到后续阶段。 | |

**User's choice:** 大爆炸替换
**Notes:** 用户倾向于高风险高回报的一次性替换策略，不接受双引擎长期并行。

## 电磁学支持深度

### 新增电磁学功能

| Option | Description | Selected |
|--------|-------------|----------|
| 更多场类型 | 电偶极子场、磁偶极子场、均匀电场/磁场之外的非均匀场（如螺线管磁场） | |

**User's choice:** 场-源关系、时变电磁场
**Notes:** 用户需要电荷/电流产生场的场-源关系，以及时变电磁场支持。

## 场-源计算方案

| Option | Description | Selected |
|--------|-------------|----------|
| 实时N体计算 | 每个电荷/电流源实时计算对所有实体的场贡献，O(N²)复杂度。精确但性能开销大。 | |
| 预计算场网格 | 将空间离散化为网格，每个格点预计算总场强。实体查询最近格点插值。牺牲精度换性能。 | |
| 混合方案 | 近场用实时计算，远场用网格近似。 | |
| 由planner决定 | 由planner根据架构一致性确定最佳方案。 | ✓ |

**User's choice:** 由planner决定
**Notes:** 用户将场-源计算的具体技术方案决策权交给planner。

---

## 时变电磁场范围

| Option | Description | Selected |
|--------|-------------|----------|
| 完整Maxwell方程组 | 数值求解完整Maxwell方程组（FDTD/FEM方法），支持电磁波传播、辐射、散射。计算极重。 | |
| 简化时变模型 | 仅支持法拉第电磁感应定律和安培-麦克斯韦定律，不考虑电磁波传播。计算量适中。 | ✓ |

**User's choice:** 简化时变模型
**Notes:** 用户最初对时变范围不确定（"暂定"），后确认选择简化时变模型。完整Maxwell方程组暂不涉及，研究阶段可能细化。

## 性能预期

| Option | Description | Selected |
|--------|-------------|----------|
| 教学演示级别 | 少量实体（≤10电荷/电流源），30fps即可接受，精度要求不高 | |
| 中等规模模拟 | ≤50实体，维持60fps，需要合理的物理精度 | |
| 由planner决定 | 由planner评估各引擎在这两个特性上的性能表现后给出建议 | |

**User's choice:** ≤50实体，目标100fps
**Notes:** 用户自定义回答：50实体但要100fps。这是一个非常高的性能约束，对Web端物理引擎是严峻挑战。
