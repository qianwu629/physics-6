# Plan 07-03: ForceFieldSystem 缓存 + VectorRenderer 性能优化

## Objective
消除 VectorRenderer 每 20ms 重复计算 O(entities × fields) 力场求和的性能瓶颈，通过模块级缓存让 ForceFieldSystem 和 VectorRenderer 共享计算结果。

## Context
`VectorRenderer.tsx` 第 228-253 行在 `useFrame` 中每 20ms 调用 `computeTotalForce(forceFields, pos, vel, bodyCharge)` 对每个 dynamic 实体计算力场力。与此同时 `ForceFieldSystem.tsx` 在 120Hz 的 `useBeforeStep` 中也对每个 dynamic 实体调用 `computeNonMagneticForce` 计算完全相同的力。50 实体 × 5 力场 × 50Hz = 12,500 次力场求和/秒，完全重复。

已有模式可参考：`frontend/src/components/contactForceStore.ts` 使用模块级 Map + timestamp 缓存接触力。

在 `ForceFieldSystem.tsx` 的 `useBeforeStep` 中，对每个 dynamic 实体计算完 `F`（非磁场力）后：
1. 导入 `setFieldForce` from './fieldForceStore'
2. 在 `body.addForce(F, true)` 之前（或之后）调用 `setFieldForce(entityId, F)`
3. 磁场力（罗德里格斯旋转）不写入 fieldForceCache，因为磁场力不通过 addForce 施加，且 VectorRenderer 的力箭头应反映实际受力。但磁场力不写入缓存，VectorRenderer 自行计算磁场力或忽略（按现有逻辑，field 类型箭头只显示非磁场力）。

注意：零向量（F.x === 0 && F.y === 0 && F.z === 0）也应写入缓存，这样 VectorRenderer 可以区分"力为零"和"缓存未命中"。
</action>
