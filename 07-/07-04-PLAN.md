# Plan 07-04: SpringRenderer BufferGeometry 内存优化

## Objective
消除 `SpringRenderer` 每帧 `new TubeGeometry()` 造成的 GPU 内存抖动，改用预分配 `BufferGeometry` + 每帧更新顶点数据。

## Context
`SpringRenderer.tsx` 第 138-148 行：`useFrame` 中每帧执行 `geometryRef.current.dispose(); geometryRef.current = new THREE.TubeGeometry(curve, ...)`。TubeGeometry 构造函数内部生成大量顶点数据（径向分段 ×  tubular 分段），每帧创建和销毁造成 GC 压力和 GPU 内存波动。

`generateHelixPoints` 生成螺旋路径点，顶点数 = coils × 16 + 1（最大 16 × 16 + 1 = 257 个点）。每个点 3 个 float，总顶点数据约 771 floats。

参考模式：`TrajectoryRenderer` 已有的 `BufferGeometry` 更新模式。

<action>
在 `SpringRenderer.tsx` 中重构几何体管理：
1. 删除 `geometryRef`（TubeGeometry ref）
2. 添加 `bufferGeoRef = useRef<THREE.BufferGeometry | null>(null)`
3. 在组件顶层（或 useMemo 中）预分配 BufferGeometry：
   ```typescript
   const MAX_VERTICES = 16 * 16 + 1; // max coils * segments + 1
   const bufferGeo = useMemo(() => {
     const geo = new THREE.BufferGeometry();
     const positions = new Float32Array(MAX_VERTICES * 3);
     geo.setAttribute('position', new THREE.BufferAttribute(positions, 3));
     geo.setDrawRange(0, 0);
     return geo;
   }, []);
   ```
4. 修改 JSX 中的 `<mesh>`：删除 `geometry={new THREE.TubeGeometry(initialCurve, 64, 0.03, 8, false)}`，改为 `ref` 方式或直接使用 `bufferGeo`
5. 注意：初始静态 mesh 也需要处理。可以将初始状态通过同样的 BufferGeometry 更新逻辑设置，或者在 `useMemo` 时预计算初始顶点
</action>

<description>每帧更新 BufferGeometry 顶点数据</description>
<read_first>
- frontend/src/components/SpringRenderer.tsx（useFrame 部分）
</read_first>
<action>
在 `useFrame` 中替换 TubeGeometry 重建逻辑：
1. 保留 `generateHelixPoints` 和 `CatmullRomCurve3` 调用（路径生成不变）
2. 删除 `curve = new THREE.CatmullRomCurve3(helixPoints)` 后的 TubeGeometry 创建逻辑
3. 改为：沿 helix 路径采样更密集的点（TubeGeometry 原本会自动细分），或直接用 helixPoints 作为顶点
4. 更新 BufferGeometry：
   ```typescript
   const posArray = bufferGeo.attributes.position.array as Float32Array;
   let idx = 0;
   for (const point of helixPoints) {
     posArray[idx++] = point.x;
     posArray[idx++] = point.y;
     posArray[idx++] = point.z;
   }
   bufferGeo.attributes.position.needsUpdate = true;
   bufferGeo.setDrawRange(0, helixPoints.length);
   ```
5. 若需要更平滑的 tube 外观（BufferGeometry 直接画线段而非 tube），可改用 `THREE.Line` 而非 `THREE.Mesh`，但视觉风格会改变（从粗管变细线）。为保持 tube 外观，需沿路径生成 tube 顶点（比较复杂）。

**推荐简化方案**：改用 `Line2`（from three/examples/jsm/lines/Line2.js）或直接用 `THREE.Line` 配合较粗的 `LineBasicMaterial.linewidth`。但更简单的方案是保持 Mesh，沿 helix 路径每段生成矩形截面顶点。

**实际可行方案**：由于 helix 点已经密集（最多 257 个点），直接用 `THREE.Line` 渲染 helix 路径，视觉上与 tube 差异不大（粗细可用 Line2）。为最小改动，先改用 `Line` + 较粗线宽。

若必须保持 tube 外观，可沿 helix 路径生成 tube 网格顶点（每个 helix 点处生成圆周上的 N 个顶点）。但这比较复杂。

决策：先用 `THREE.Line` 替代，视觉影响可控。若验收不通过再升级为 tube 顶点生成。
</action>

```tsx

  <lineBasicMaterial color={isSelected ? '#3299ff' : '#888888'} linewidth={2} />
</line>
```

注意：`linewidth` 在 WebGL 中通常被限制为 1。需要更粗线条时可用 `Line2` from `three/examples/jsm/lines/Line2.js` + `LineMaterial`。但这增加依赖。先接受细线，Phase 6 性能优化时再考虑 Line2。
