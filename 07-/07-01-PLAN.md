# Plan 07-01: RigidBodyRefContext 竞态修复 + 类型安全

## Objective
修复 `RigidBodyRefContext` 注册表在实体快速添加/删除时的竞态条件，并消除代码中 6 处 `as any` 类型逃逸。

## Context
`Scene3D.tsx` 中的 `rigidBodyRefMap` 是 naive Map：register 直接 set，unregister 直接 delete。当 `EntityRenderer` unmount 时调用 unregister，但 `ForceFieldSystem` 的 `useBeforeStep`（在 R3F useFrame 中执行）或 `VectorRenderer` 的 `useFrame` 可能在同一帧稍后仍调用 `getRef`，获取到已删除的 entry 或 `current === null` 的 ref，导致崩溃。

<id>1</id>
<description>扩展 RigidBodyRefContext 接口为引用计数注册表</description>
<read_first>
- frontend/src/components/RigidBodyRefContext.tsx
- frontend/src/components/Scene3D.tsx（第 207-217 行注册表实现）

<action>
在 `RigidBodyRefContext.tsx` 中：
1. 添加 `RegistryEntry` 接口：`{ ref: RefObject<RigidBodyAPI | null>; refCount: number; mounted: boolean }`
2. 修改 Context 类型：`getRef` 返回 `RefObject<RigidBodyAPI | null> | undefined` 保持不变，但内部使用引用计数。
3. `Scene3D.tsx` 中替换 `rigidBodyRefMap` 实现：
   - `registerRef`: 若 entry 已存在则 refCount++ 并更新 ref；否则新建 entry（refCount=1, mounted=true）
   - `unregisterRef`: refCount--；若 refCount <= 0 则设置 mounted=false 并延迟 100ms 后删除（给 consumer 一帧缓冲期）
   - `getRef`: 检查 `entry.mounted === true && entry.refCount > 0`，否则返回 undefined
</action>
<acceptance_criteria>
- `RigidBodyRefContext.tsx` 包含 `interface RegistryEntry`
- `Scene3D.tsx` 的 `registerRef` 实现中包含 `refCount++` 逻辑
- `Scene3D.tsx` 的 `unregisterRef` 实现中包含 `setTimeout(() => {...}, 100)` 延迟删除
- `Scene3D.tsx` 的 `getRef` 实现中包含 `entry.mounted === true && entry.refCount > 0` 检查
</acceptance_criteria>
</task>
