项目概览

physics4 是一个基于 Rapier 的自定义物理引擎项目，核心目标是支持电磁学模拟与力场可视化。项目采用 TypeScript 前端与物理计算模块分离的架构，并通过 GSD（Goal-Structured Development）工作流分阶段推进。

一、项目范围与技术栈

⚛️ 物理引擎核心

核心

基于 Rapier 构建自定义物理引擎，扩展支持电磁学力场，包括库仑力、洛伦兹力、电场与磁场模拟。

关键技术：力场积分、数值稳定性、刚体受力、罗德里格斯旋转公式。

🎨 可视化系统

前端

力场对话框、力场系统、3D 场景、向量渲染器、刚体引用上下文等组件，实现电磁场的实时可视化。

主要文件：ForceFieldDialog.tsx、ForceFieldSystem.tsx、Scene3D.tsx、VectorRenderer.tsx。

🧪 测试与验证

质量

包含力场计算单元测试（forceFieldCalc.test.ts），验证电磁力计算的正确性与数值稳定性。

调试工具：诊断脚本、Python 辅助工具、GSD 验证代理。

三、核心调试战役

physics4 项目中最具代表性的两次深度调试，展现了从症状到根因的完整追溯能力。

⚡ 战役一：洛伦兹力积分数值不稳定性（能量爆炸）

症状：模拟中能量异常爆炸式增长，系统数值发散。

根因：洛伦兹力积分存在数值不稳定性，简单的欧拉或半隐式积分无法保持能量守恒与方向正确性。

修复：使用罗德里格斯旋转公式（Rodrigues' rotation formula）对速度方向进行数学上严谨的旋转，确保洛伦兹力作用下速度矢量的正确演化。

已修复 数学严谨
⚡ 战役二：同种电荷排斥力误诊

症状：带电物体下落速度异常，似乎比预期更快。

初诊：最初被误判为重力或阻尼相关的问题。

根因：实际上是同种电荷之间的排斥力在起作用，导致带电体在垂直方向上产生额外加速度分量，表现为下落速度异常。

启示：在电磁学模拟中，多体力耦合容易产生看似无关的症状，必须从力场叠加原理出发系统分析。

已定位 诊断转折点

六、physics4 项目中的摩擦与教训

❌ 初诊误诊导致修正循环

在电磁学调试中，Claude 的首次诊断多次偏离正确方向（如把电荷排斥力误诊为重力问题）。昴君需要额外轮次才能回到正确路径，消耗了本可避免的时间。

教训：对物理模拟问题，应先列出所有作用力并做量纲/方向检查，再做症状归因。

❌ 自动修复引入回归

使用自动代码审查 --fix 时，修复代理曾引入编译错误（缺失 using、语法错误）。physics4 项目虽有大量 TypeScript，但任何多文件改动都需要事后验证。

教训：多文件编辑后必须运行测试或语法检查，不能仅凭代理报告宣告成功。

❌ GSD 工作流执行偏离

Claude 在 physics4 的 GSD 阶段中曾多次直接执行计划而不是按规范使用子代理/工具，导致验证失败或结果不符合预期，昴君需要介入纠正。

教训：讨论/规划阶段用子代理，执行阶段用直接工具，验证阶段用自动化测试，三者不可混淆。

七、针对 physics4 项目的建议

可加入项目 CLAUDE.md 的规则

1. 物理模拟改动必须事后验证

规则：任何修改力场计算、积分器、刚体受力逻辑的改动后，必须运行 forceFieldCalc.test.ts 或相关测试，并检查能量守恒/数值稳定性。

原因：physics4 的核心风险是数值发散，洛伦兹力能量爆炸就是前车之鉴。

2. 多力耦合问题先做受力清单

规则：当带电刚体运动异常时，先列出所有作用力（重力、电场力、磁场洛伦兹力、阻尼、接触力）并检查方向和量纲，再定位 Bug。

原因：同种电荷排斥误诊事件说明，电磁学中的异常运动极易被误判为单一力问题。

3. GSD 阶段工具映射

规则：physics4 的 GSD 阶段中，Phase 0 讨论用子代理；Phase 1-8 规划用 planner 子代理；Phase 执行阶段只使用 Bash/Edit 等直接工具；验证阶段运行测试套件，不 spawning 验证代理。

原因：避免执行偏离和级联错误。

4. 中文优先回复

规则：昴君用中文沟通时，默认中文回复。

原因：减少语言切换摩擦，让昴君专注于物理问题本身。

推荐使用的 Claude Code 功能

Hooks：物理改动后自动跑测试

在 .claude/settings.json 中配置：当修改 forceFieldCalc.ts 或相关物理文件后，自动运行对应测试，捕获数值回归。

Custom Skills：physics4 专用规划 skill

创建 /gsd-physics4 skill，内置物理引擎项目的阶段模板和工具映射，减少每次重新说明工作流。

并行验证代理（审慎使用）

对复杂物理改动，可 spawning 专门代理分别验证：能量守恒、边界情况、可视化一致性，但验证结果必须通过自动化测试最终确认。
